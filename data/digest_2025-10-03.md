### Jeff Bezos says AI is in a bubble but society will get 'gigantic' benefits

#### [Submission URL](https://www.cnbc.com/2025/10/03/jeff-bezos-ai-in-an-industrial-bubble-but-society-to-benefit.html) | 232 points | by [belter](https://news.ycombinator.com/user?id=belter) | [521 comments](https://news.ycombinator.com/item?id=45464429)

**Bezos Says AI is in a Bubble—But the Revolution is Real**  

Jeff Bezos has weighed in on the AI hype cycle, acknowledging that the industry shows signs of a bubble—with sky-high valuations, overexcitement, and a flood of funding for both good and bad ideas—yet he insists AI’s transformative power is undeniable. Speaking at Italian Tech Week, the Amazon founder compared the current AI frenzy to past market bubbles, like the dot-com crash, but emphasized that the long-term impact will be enormous.  

### **The Signs of an AI Bubble**  
- **Disconnected Valuations:** Stock prices and investments in AI are surging beyond fundamentals.  
- **Frenzied Funding:** Startups—even tiny ones—are raising billions, often without clear differentiation between viable and doomed ventures.  
- **Historical Parallels:** Bezos pointed to the 1990s biotech bubble, which, despite many failures, led to breakthrough drugs.  

### **Why AI is Still a Game-Changer**  
Despite the hype, Bezos believes AI will "change every industry" and deliver "gigantic" societal benefits. The key difference between AI and past bubbles? The underlying technology is **real**—not just speculative optimism.  

### **Other Heavyweights Sound the Alarm**  
- **Sam Altman (OpenAI):** Warned earlier this year that AI is in a bubble.  
- **David Solomon (Goldman Sachs):** Cautioned that market excitement often overlooks risks, predicting a "reset" at some point.  
- **Karim Moussalem (Selwood Asset Management):** Compared AI investing to "speculative manias" of history.  

### **Bottom Line**  
Bubble or not, AI isn’t going away—the winners will reshape our future, even as overhyped players fade. As Bezos puts it: *"When the dust settles… society benefits from those inventions."*

### Jules, remote coding agent from Google Labs, announces API

#### [Submission URL](https://jules.google/docs/changelog/) | 191 points | by [watkajtys](https://news.ycombinator.com/user?id=watkajtys) | [56 comments](https://news.ycombinator.com/item?id=45466588)

# 🎯 Jules CLI and More: Google's AI Coding Assistant Gets a Major Upgrade  

Google's AI coding assistant **Jules** just dropped a 🔥 set of new features, turning it into a **powerhouse for developers**. Whether you're a CLI lover or prefer a guided UI, Jules now fits seamlessly into your workflow.  

### 🚀 **Top Highlights**  

1. **Jules CLI is Here!** *(Oct 2, 2025)*  
   - **Scriptable:** Pipe commands from tools like `gh` or `jq` to automate tasks.  
   - **Apply Patches Locally:** Pull Jules’ work-in-progress code with `jules remote new` and test before committing.  
   - **Interactive Mode:** Prefer a TUI? Use `jules tui` for a guided dashboard.  
   - **Install:**  
     ```bash  
     npm install -g @google/jules  
     # or run on-the-fly  
     npx @google/jules  
     ```  

2. **Jules Memory for Repos** *(Sep 30, 2025)*  
   - Learns from your corrections/feedback and applies them in future tasks (**context-aware coding**).  
   - Toggle on/off in repo settings under **"Knowledge."**  

3. **Precision File Selection** *(Sep 29, 2025)*  
   - Pinpoint exactly which files Jules should modify—no more guessing.  

### 🤖 **Other Cool Updates**  

- **PR Comment Reactions** *(Sep 23)*: Jules now 👀reads GitHub PR feedback and auto-pushes fixes (opt-in via **@Jules** mentions).  
- **Image Uploads** *(Sep 9)*: Show UI bugs or design mocks (JPEG/PNG ≤5MB).  
- **Stacked Diffs** *(Sep 4)*: Review multi-file changes in **one scrollable view**.  
- **Better Critic Mode** *(Sep 3)*: See Jules’ real-time code analysis—like a pair programmer explaining their reasoning.  

**P.S.** Pirate mode is (sadly) over, but **image rendering in diffs** (Aug 22) and **sample prompts** are here to stay.

### **Summary of Hacker News Discussion on Jules CLI & AI Coding Assistant**  

The discussion revolves around **Google’s Jules AI coding assistant**, with mixed reactions on its usefulness, trustworthiness, and practicality in development workflows.  

#### **Key Themes:**  

1. **Workflow Improvements & Use Cases**  
   - Some users report significant **time savings**, especially in handling **PR reviews, infrastructure changes, and automated fixes**.  
   - Jules' **CLI integration** is praised for allowing **direct modifications + testing before commits** (`jules remote new`).  
   - One user moved infrastructure to **Railway** with Jules handling PRs, reducing customer review cycles.  

2. **Limitations & Frustrations**  
   - **Rate-limiting and throttling issues** (e.g., 15 tasks/day on free tier, slow processing times).  
   - **Unreliable code correctness**—Jules sometimes introduces bugs or fails to maintain context over long sessions.  
   - **UI/UX complaints**, such as **slow rendering in diffs** and confusing state management.  

3. **AI Trust & Security Concerns**  
   - Some **hesitate to fully trust AI-generated code**, fearing security flaws (e.g., IDOR vulnerabilities introduced by LLMs).  
   - Counterarguments: The **human review layer (PR checks)** mitigates blind trust in Jules’ suggestions.  

4. **Comparisons with Alternatives**  
   - **Claude Code vs. Jules:** Users debate which is better, but many prefer Claude’s reliability or Gemini Code Assist for scripting.  
   - **Aider & SWE-agent** are mentioned as **alternatives** offering **collaborative AI agents** for coding.  

5. **Broader AI Developer Tools Debate**  
   - Skeptics argue AI coding tools **"aren’t reliable enough yet"** and may discourage deep engineering understanding.  
   - Optimists believe they **accelerate workflows**, even if they **require supervision**.  

#### **Notable Takeaways:**  
- **For small, repetitive tasks** (like PR checks), Jules **can be valuable**.  
- **For production-critical changes**, human review remains **essential**.  
- Improvements are still needed in **processing speed, reliability, and context retention**.
