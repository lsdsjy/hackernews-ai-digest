# Unlocking Your Monitor’s Potential with Linux’s KMS API

Tired of letting your display hardware's capabilities go untapped? In this hands-on exploration of Linux's Kernel Mode Setting (KMS) API, we'll take direct control of your monitors – query their settings, configure displays at a low level, and even render 3D animations without a compositor. And the best part? You can follow along interactively using OCaml bindings that make the notoriously complex DRM API more approachable.

## Why Care About KMS?

- Get under the hood of display management instead of depending on Wayland/X11
- Optimize displays for specialized use cases (HUDs, kiosks, media players)
- Understand how compositors actually work at a systems level
- Learn techniques useful for low-latency or high-performance applications

## Quick Start: Your Interactive Playground

Want to try this live? With just a few commands in Nix or opam you'll have a REPL where you can:
- Discover connected monitors and their capabilities  
- Switch resolutions on the fly  
- Create framebuffers directly  
- Render content with atomic precision  

## Deep Dive: The Hardware Pipeline

We'll explore the key components that make displays work:

1. **Connectors** (your physical monitor ports) - find out which are active and supported resolutions
2. **CRTCs** (display controllers) - the brains that drive each screen
3. **Framebuffers** - where your pixels actually live  
4. **Encoders** - translate digital signals for different connector types  

The post includes a handy visualization showing how these pieces interconnect to form a complete display pipeline.

## From Static to Dynamic

Starting with basic queries ("What monitors do I have?"), we progress to:
- Non-atomic changes (simple but limited)
- Atomic mode setting (transactional display changes)
- Creating "dumb buffers" for raw pixel data
- Finally: Hardware-accelerated 3D rendering

## Debugging Like a Pro

Learn essential troubleshooting techniques for when things go wrong:
- Checking DRM capabilities  
- Interpreting kernel messages  
- Switching between virtual terminals  
- Recovering from bad configurations  

Whether you're building a custom display stack or just want to understand how Linux drives modern monitors, this guide gives you the tools and conceptual framework to work directly with display hardware. The OCaml bindings provide an unusually clear window into these typically opaque operations.
